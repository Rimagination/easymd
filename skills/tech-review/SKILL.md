# 科技评论图文写作

写原创的科技新闻分析、解释性报道和评论。借鉴高质量科技报道对技术机制、真实应用和社会影响的关注；不沿用任何媒体的固定措辞、标识或版式，也不声称与《MIT 科技评论》有关。

在 easymd 工作流中负责选题、核实、成稿和配图方案；排版、封面制作及草稿上传由 easymd 按需求路由。

## 开始写作

- 从用户给定的主题、材料、读者和发布平台出发。缺少可决定文章方向的信息时，先利用已有材料形成一个可检验的选题判断；只有确实无法判断时才提一个具体问题。
- 提炼一条中心判断：发生了什么变化，证据是什么，谁会受到影响，以及目前卡在哪里。区分已经验证的能力、实验结果、商业承诺和推测。
- 对新闻时效、数字、论文、政策、产品能力及争议事实查找当前来源。优先论文原文与补充材料、公开数据、监管文件、产品文档、企业披露和具名采访；关键争议再寻找独立证据。保留原始链接和发布日期。
- 仅凭新闻稿、摘要或转述无法核实的细节，写明来源与不确定性。不得编造采访、场景、引语、实验结果或图片来源。

当用户强调公众号阅读表现或要求提高传播潜力时，阅读 [公众号选题与图文表现](references/wechat-readership.md)，据此比较候选角度、标题和封面。把预期阅读当成待检验的编辑判断，不承诺流量。

## 文章写法

- 标题点出可核实的新变化或真实矛盾，导语尽快给读者一个具体事实、人物经历或数据。没有经核实的现场材料时，从事实开篇。
- 标题尽量写清对象、变化及读者关心的后果；只有问题本身足够具体时才使用问句。为公众号稿件给出几种不同切口的标题，并说明首选理由。
- 用普通读者能理解的语言解释技术机制，保留决定结论的关键条件、指标和适用范围。术语首次出现时解释；类比不能代替机制。
- 让证据推动叙事：技术做到了什么、对照基线是什么、部署要付出什么、失败或争议在哪里、谁获益或承担成本。按选题取舍，不套固定段落模板。
- 把事实、来源观点和作者分析分开表达；风险、收益与前景按证据强度措辞。结尾落到下一项可观察的验证、现实后果或未解问题。
- 中文表达具体、克制、有节奏。删掉空泛赞词、悬空的“业内人士认为”和重复总结；避免“不是……而是……”句式。

## 图文交付

- 每张图承担一项任务：展示现场或实物、解释机制、比较数据、标明时间线，或帮助读者看清关键限制。按内容需要决定张数和位置。
- 用户要完整图文时，使用可用工具生成原创解释图或取得可用的授权图片，并在文章 Markdown 中放入实际图片。纪实场景使用有来源、可用的真实照片；生成图不得伪装为真实现场、实验结果或数据图。
- 图表必须可追溯到数据及处理方法。图片配简短图注、来源或生成说明、替代文本；封面另给一行概念说明。缺少图片工具、授权或原始数据时，交付明确的配图清单和制作说明，不用占位图冒充成品。

## 交付与自检

- 默认交付可编辑的 Markdown：标题、导语、正文、就位图片或配图清单、文末来源链接。通过 easymd 生成公众号草稿时，遵守 easymd 的编号角标与文末“参考资料／参考文献”格式，网址写为明文，不用 Markdown 超链接。公众号排版或发布由相应工具处理，仅在用户要求时执行。
- 发布前核对所有关键数字、日期、人物身份、论文结论、引语、图片权属与正文链接。检查标题和图片有没有超出证据；把尚待核实的重点单列给用户。
- 用户只要选题、提纲或改稿时，只交付该阶段需要的内容。文章长度随题材和平台调整。
