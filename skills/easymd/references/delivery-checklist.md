# 交付检查清单

这个文件给 easymd Skill 在最终交付前使用。目标是让 Agent 像编辑一样检查文章，而不是只把 Markdown 转成 HTML。

## 产品边界检查

- 已经把 easymd Web 和 easymd Skill 看作两个产品：网站负责可视化编辑，Skill 负责 Agent 文章制作。
- 没有把网站操作步骤当成唯一交付路径；没有 MCP 时也能用组件库手写 HTML。
- 没有承诺写入微信公众号草稿箱、自动发布或读取用户微信凭证。
- 没有使用已移除平台或旧 REST API 示例。

## 内容检查

- 标题明确，能说明文章主题或读者收益。
- 开篇导读不超过 4 行，说明问题、读者和结果。
- 章节标题能构成文章目录，不只是装饰短语。
- 每个 callout 都有真实提醒价值，不重复正文。
- 金句框只放短而有力的句子，不放长段落。

## 视觉检查

- 至少使用一种结构组件：导读卡、章节标题、信息卡片、步骤列表、callout、金句框或文末行动。
- 如果用户要求“精排”或“公众号文章”，优先使用组件化精排，而不是只输出普通 Markdown 渲染结果。
- SVG 信息图使用内联 SVG，文字没有贴边，移动端宽度友好。
- 颜色不只依赖单一色相；主色、背景和强调色有区分。
- 表格列数过多时提醒用户在 easymd Web 预览后复制。

## 技术检查

- HTML 尽量使用内联样式，适合复制到公众号编辑器。
- 图片 URL 可公开访问；本地图片要提醒用户先上传或替换。
- 外部链接在微信场景下默认使用脚注或引用说明。
- 代码块较长时提醒检查移动端可读性。
- 输出中没有 `<script>`、外链 CSS 或依赖网站运行时的类名。

## 交付格式

- 用户要可复制结果时，交付 HTML 片段。
- 用户要继续编辑时，同时给 Markdown 或结构说明。
- 用户要发布前确认时，说明“复制到公众号编辑器后请预览移动端”。
- 不把截图当成最终交付，除非用户明确只要视觉预览。
